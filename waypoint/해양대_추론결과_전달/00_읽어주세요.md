# 추론 용접선 웨이포인트 전달 자료

작성 2026-09-02
보내는 내용 AI 모델이 3D 점군에서 뽑아낸 용접선 경로와 그 검증 자료

---

## 1. 무엇을 보내는가

해양대에서 받은 66조건 점군에 학습된 모델을 돌려 용접선을 찾고,
그 점들을 하나의 경로로 이어 로봇이 따라갈 웨이포인트로 만든 것이다.

카메라를 달지 않고 이미 촬영된 점군을 쓰는 상황이라고 들었다.
그래서 픽셀에서 3차원으로 되돌리는 계산은 필요 없다.
이미 3차원 좌표로 넘긴다. 단위는 전부 mm 다.

| 폴더 | 내용 |
| --- | --- |
| `01_웨이포인트` | 로봇에 넣을 좌표 CSV |
| `02_시각화_조건별` | 조건마다 한 장씩, 66장 |
| `03_시각화_요약` | 전체 경향을 보는 그림 5장 |
| `04_재현절차` | 이 결과를 다시 만드는 절차와 스크립트 |

## 2. 좌표계를 먼저 확인해 주세요

가장 중요한 항목이다. 이것을 놓치면 로봇이 거울상 위치로 움직인다.

`rs2_deproject_pixel_to_point()` 가 내놓는 RealSense 카메라 좌표계는
x 가 오른쪽, y 가 아래, z 가 앞(카메라에서 멀어지는 방향)이다.
z 는 깊이이므로 항상 양수다.

그런데 전달받은 PLY 파일은 z 가 전부 음수다.
y 가 위, z 가 뒤를 향하는 다른 규약으로 저장되어 있다.
확인해 보니 CloudCompare 를 거치면서 축이 바뀐 것으로 보인다.

그래서 CSV 에 좌표를 세 벌 넣었다.

| 열 이름 | 좌표계 | 언제 쓰나 |
| --- | --- | --- |
| `x_raw_mm`, `y_raw_mm`, `z_raw_mm` | PLY 원본 그대로 | 원본 점군 위에 겹쳐 그려 확인할 때 |
| `x_cam_mm`, `y_cam_mm`, `z_cam_mm` | RealSense 카메라 좌표계 | `rs2_deproject_pixel_to_point()` 결과와 같은 프레임으로 맞출 때 |
| `x_local_mm`, `y_local_mm`, `z_local_mm` | 경로 시작점이 원점 | 로봇 작업대 위에 올려 형상만 확인할 때 |

`cam` 은 `raw` 에 (x, -y, -z) 를 적용한 값이다. 이미 계산해서 넣어 두었으니
따로 부호를 뒤집을 필요는 없다.

### 로봇에 올릴 때는 local 을 쓰는 편이 낫다

`raw` 와 `cam` 은 카메라를 원점으로 한 좌표다.
시편이 카메라에서 323 ~ 1,300 mm 떨어진 곳에 있어서 그 값이 그대로 들어 있다.
Mirobot 의 작업 반경을 넘어가는 값이므로 그대로 넣으면 도달하지 못한다.

`local` 은 경로 시작점을 원점으로 놓고 경로가 놓인 평면을 XY 로 맞춘 값이다.
첫 점이 (0, 0, 0) 이고 나머지가 거기서부터의 상대 위치다.
작업대 위 원하는 곳에 원점을 잡고 그대로 더하면 된다.

66조건 전체에서 local 좌표가 차지하는 범위는 다음과 같다.

| 축 | 범위 |
| --- | --- |
| x (경로 길이 방향) | 0 ~ 298.2 mm |
| y (좌우) | -24.0 ~ 16.6 mm |
| z (위아래) | -8.5 ~ 6.0 mm |

경로는 거의 평면 위에 놓인 300mm 짜리 선이다.
Mirobot 작업 반경 안에 들어가는지 먼저 확인해 주시고,
넘으면 축척을 줄인 버전을 만들어 드리겠다. 말씀만 주시면 된다.

### Tool Offset 은 별개다

`$46`, `$47`, `$48` 로 설정하는 Tool Offset 과 `custom_tool_offset(x, y, z)` 는
공구 끝점을 옮기는 값이라 이 경로 좌표와는 별개다.
경로는 용접선 자체의 위치이고, Offset 은 그 위치에 어느 지점을 갖다 댈지를 정한다.
둘 다 mm 단위이므로 단위 변환은 필요 없다.

## 3. CSV 읽는 법

### 추론_용접선_웨이포인트.csv

경로를 이루는 점을 순서대로 담았다.

| 열 | 뜻 |
| --- | --- |
| `condition` | 조건 이름. 예를 들어 `WELD_D04_L1_A000` 은 두께 4mm, 용접선 L1, 회전 0도 |
| `seq` | 그 조건 안에서의 순서. 0 부터 시작한다 |
| `x_raw_mm` 외 9개 | 위에서 설명한 좌표 세 벌 |
| `status` | 정상 / 검토필요 / 산출불가 |

`seq` 순서대로 이으면 그것이 경로다. 중간에 건너뛰거나 정렬을 바꾸면 안 된다.

`status` 가 `검토필요` 인 조건은 모델 신뢰 신호가 낮아 사람이 한 번 볼 필요가 있다는 뜻이다.
이번 66조건에는 검토필요와 산출불가가 없다. 전부 정상이다.

### 추론_용접선_요약.csv

조건마다 한 줄로 경로의 성질을 담았다. 66행이다.
어느 조건을 먼저 시험할지 고를 때 쓰면 된다. IoU 가 높은 4mm 조건부터 권한다.

| 열 | 뜻 |
| --- | --- |
| `조건` | 조건 이름 |
| `판재두께_mm`, `용접선`, `시편회전_도` | 조건 이름을 나눠 담은 것 |
| `판사이각도_도` | 두 판이 실제로 이루는 각도. 점군에서 측정한 값 |
| `판정` | 정상 / 검토필요 / 산출불가 |
| `웨이포인트_개수` | 그 조건의 웨이포인트 수 |
| `경로길이_mm` | 경로 전체 길이 |
| `용접선IoU_퍼센트` | 모델이 용접선 점을 얼마나 맞혔는지 |
| `라벨대비편차_mm` | 라벨 용접선 점에서 경로까지의 평균 거리 |
| `해양대교선과의거리_mm` | 해양대가 낸 교선과 우리 경로 사이 거리 |
| `평균확률`, `유효구간비율` | 모델 신뢰 신호. 판정의 근거가 되는 값 |
| `추론용접점_개수` | 모델이 용접선으로 분류한 점 수 |
| `접촉5mm라벨_개수`, `해양대3mm밴드_개수` | 두 라벨 기준의 점 수 비교 |
| `수동라벨_있음` | 없음이면 라벨을 복원해 쓴 조건. 2건 있다 |

`수동라벨_있음` 이 없음인 조건은 `WELD_D08_L1_A000` 과 `WELD_D12_L1_A000` 이다.
이 두 조건만 수동 라벨 파일이 전달되지 않아서, 3mm 밴드로 표시된 점을
가까운 판으로 되돌려 라벨을 복원했다.
경로 자체는 다른 조건과 같은 방식으로 뽑았으니 로봇 시험에 쓰는 데는 문제가 없다.
다만 이 두 조건의 IoU 는 복원한 라벨과 비교한 값이라 다른 조건보다 근거가 약하다.

## 4. 그림 보는 법

조건별 그림 한 장에 세 부분이 있다.

왼쪽 위는 모델이 무엇을 용접선으로 인식했는지를 3차원으로 본 것이다.
점을 세 가지로 나눠 칠했다.

| 색 | 뜻 |
| --- | --- |
| 초록 | 맞힘. 라벨도 용접선이고 모델도 용접선이라고 한 점 |
| 파랑 | 놓침. 라벨은 용접선인데 모델이 못 잡은 점 |
| 주황 | 잘못 잡음. 라벨은 용접선이 아닌데 모델이 용접선이라고 한 점 |

초록을 초록과 파랑과 주황을 합친 것으로 나눈 값이 요약 CSV 의 IoU 다.
그림과 숫자가 같은 것을 보고 있는 셈이다.

빨간 선이 그 점들에서 뽑아낸 경로이고, 흰 테두리를 두른 검은 점이 웨이포인트다.
회색과 연한 파랑은 시편의 두 판이다.

오른쪽 위는 용접선에 직각인 단면이다. 두 판이 이루는 각도와
경로가 어디에 놓였는지가 여기서 보인다.
빨간 X 가 우리 경로, 파란 십자가 해양대 교선 위치다.
두 표시가 떨어져 있는 정도가 두께에 따라 어떻게 달라지는지 보시면 된다.

아래는 경로가 길이 방향으로 얼마나 곧게 나왔는지다.
회색이 다듬기 전, 색이 이동평균 5구간을 거친 값이다.
회색의 뾰족한 톱니가 색 선에서 사라지는 것을 볼 수 있다.

## 5. 성능과 한계

### 전체

| 항목 | 값 |
| --- | --- |
| 조건 수 | 66건, 전부 정상 |
| 용접선 IoU | 중앙값 78.52 % |
| 경로 길이 | 중앙값 294.7 mm (273.1 ~ 308.5 mm) |
| 웨이포인트 수 | 중앙값 18개 (10 ~ 36개) |
| 라벨 대비 경로 편차 | 중앙값 2.28 mm |

웨이포인트 수는 허용오차 0.5 mm 안에서 줄인 결과다.
직선에 가까운 경로는 점이 적고, 굽은 경로는 점이 많다.

### 두께별로 크게 다르다

| 두께 | 용접선 IoU 중앙값 | 라벨 대비 편차 중앙값 |
| --- | --- | --- |
| 4 mm | 93.02 % | 2.32 mm |
| 8 mm | 78.52 % | 2.20 mm |
| 12 mm | 68.87 % | 2.31 mm |

12mm 가 낮은 이유는 모델보다 데이터 쪽에 있다.
두꺼운 판은 수직판 아래쪽이 수평판에 가려져 용접부 표면이 잘 잡히지 않는다.
조건당 용접선 라벨 점이 4mm 는 1,518점인데 12mm 는 138점이다.

다만 경로 편차 자체는 두께와 무관하게 2.2 ~ 2.3 mm 로 비슷하다.
IoU 는 용접선 점을 몇 개나 맞혔는지를 재는 값이고,
편차는 뽑아낸 경로가 실제 용접선에서 얼마나 벗어났는지를 재는 값이다.
12mm 에서 IoU 가 낮은 것은 잡은 점이 적다는 뜻이지 경로가 엉뚱한 곳에 놓였다는 뜻은 아니다.
로봇 시험은 12mm 조건에서도 해볼 만하다.

### 회전각은 영향이 작다

0~50도 무리가 78.13 %, 130~170도 무리가 79.97 % 로 거의 같다.
시편을 돌려도 인식 성능이 떨어지지 않는다.

### 실행마다 값이 달라진다. 두께에 따라 폭이 다르다

GPU 연산 순서가 고정되지 않아서 같은 입력을 같은 가중치로 돌려도
결과가 완전히 같지 않다. 66조건을 세 번 돌려 같은 조건끼리 비교한 실측값이다.

| 조건 | 3회 실행값 | 폭 |
| --- | --- | --- |
| WELD_D04_L2_A000 | 95.2 / 94.9 / 94.9 % | 0.3 %p |
| WELD_D04_L1_A050 | 91.0 / 90.7 / 89.8 % | 1.2 %p |
| WELD_D08_L1_A010 | 79.3 / 78.0 / 78.0 % | 1.3 %p |
| WELD_D12_L1_A030 | 77.9 / 79.4 / 75.6 % | 3.8 %p |
| WELD_D12_L1_A160 | 57.8 / 57.8 / 64.4 % | 6.6 %p |
| WELD_D12_L1_A000 | 49.2 / 55.0 / 48.2 % | 6.8 %p |

4mm 과 8mm 은 1.3 %p 안쪽인데 12mm 은 최대 6.8 %p 까지 흔들린다.
두께에 따라 폭이 이렇게 다른 이유는 라벨 점 수 때문이다.
12mm 은 용접선 라벨이 조건당 138점뿐이라 점 몇 개가 뒤집히면 비율이 크게 움직인다.
4mm 은 1,518점이라 같은 수가 뒤집혀도 비율은 거의 변하지 않는다.

전체 중앙값으로 보면 3회 실행이 78.52 / 79.08 / 79.74 % 였다.
보낸 CSV 와 그림은 세 번째 실행의 결과이며, 서로 같은 실행에서 나온 것이라 일관된다.

경로 좌표 자체는 이만큼 흔들리지 않는다.
경로는 용접선 점들의 구간별 중앙값으로 뽑기 때문에 점 몇 개가 바뀌어도 위치가 거의 그대로다.
로봇 시험에는 영향이 없다고 보면 된다.

## 6. 먼저 해보시면 좋을 순서

1. `WELD_D04_L1_A000` 하나만 골라 `x_local`, `y_local`, `z_local` 을 그대로 그려본다.
   `02_시각화_조건별/WELD_D04_L1_A000.png` 의 경로 모양과 같은지 눈으로 맞춰본다.
2. 모양이 맞으면 작업대 원점을 정해 더하고 로봇으로 그려본다.
3. 4mm 조건 몇 개를 더 해본 뒤 8mm, 12mm 로 넓힌다.

1번에서 모양이 안 맞으면 좌표계 문제일 가능성이 크다.
그때는 `raw` 와 `cam` 을 각각 그려보고 어느 쪽이 맞는지 알려주시면 맞춰 드리겠다.

궁금한 점이나 다른 형식이 필요하면 말씀해 주시면 된다.
