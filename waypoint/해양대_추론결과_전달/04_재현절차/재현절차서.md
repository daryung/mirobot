### 볼륨 연결

컨테이너 안에서 쓰는 경로와 호스트 경로의 대응은 다음과 같다.

| `/out` | `/root/nia_out` | 학습된 가중치 |

실행 껍데기는 `scripts/gpu_run.sh` 에 들어 있다. 사용법은 다음과 같다.

```bash
bash gpu_run.sh <스크립트이름> [인자...]
```

주의할 점이 하나 있다. 여러 스크립트를 이어서 돌릴 때 세미콜론으로 붙이면

python 을 찾지 못하고 종료 코드 127 로 끝난다.
시드를 여러 개 돌릴 때는 반드시 `docker run` 을 시드마다 따로 띄워야 한다.

## 2. 데이터

### 원본

해양대에서 받은 자료는 66조건이다.
판재 두께 3종(D04, D08, D12) × 용접선 2종(L1, L2) × 시편 회전 11종.

회전각은 0~50도와 130~170도 두 무리로 나뉜다.
A000, A010, A020, A030, A040, A050, A130, A140, A150, A160, A170 이다.
10도 간격으로 0도부터 170도까지 죽 훑은 것이 아니라 두 구간만 촬영되어 있다.

각도를 다양하게 한 시편이 맞는지 확인해 달라는 요청이 있었는데, 맞다.
파일 이름만 믿지 않고 점군에서 두 판이 이루는 각도를 직접 재어 보았다.
중앙값 86.91도, 범위 65.20 ~ 89.88도로 조건마다 실제로 다르다.

| 폴더 | 내용 |
| --- | --- |
| `04_원본_및_수동라벨` | 수동 라벨 PLY 64조건. scalar_class 는 0 배경 / 1 수평판 / 2 수직판 |
| `06_용접선_3mm_결과_66조건` | 교선 기준 3mm 밴드 라벨 PLY 66조건. scalar_class 에 3(용접밴드) 이 추가됨 |

수동 라벨이 64조건인 이유는 `WELD_D08_L1_A000` 과 `WELD_D12_L1_A000` 두 조건에
수동 라벨 파일이 없기 때문이다. 학습과 평가는 이 두 조건을 뺀 64조건으로 했다.

좌표 단위는 m 다. 이 작업에서는 전부 mm 로 바꿔 쓴다.

### 라벨을 다시 만든 이유

받은 라벨은 두 평면을 무한히 늘려 만나는 교선에서 3mm 안쪽의 점이다.
그런데 교선은 판 표면보다 안쪽에 있다. 판이 두꺼울수록 그 차이가 커진다.

66조건 전부에서 교선과 표면 경로 사이 거리를 재어 보았다. 중앙값 기준이다.

| 두께 | 교선에서 표면까지 | 3mm 밴드 라벨 점 수 | 접촉 5mm 라벨 점 수 |
| --- | --- | --- | --- |
| 4 mm | 3.04 mm | 506 점 | 1,518 점 |
| 8 mm | 5.88 mm | 24 점 | 343 점 |
| 12 mm | 12.52 mm | 7 점 | 138 점 |

12mm 판에서는 교선이 표면에서 12mm 넘게 떨어져 있다.
반경 3mm 밴드로는 실제 용접부 표면점이 조건당 7점밖에 잡히지 않는다.
`WELD_D12_L1_A160` 처럼 아예 0점인 조건도 있다.
라벨이 이러면 모델이 배울 것이 없다.

그래서 라벨을 교선 기준이 아니라 표면 접촉 기준으로 다시 만들었다.
같은 조건에서 접촉 5mm 기준은 138점을 잡는다.

접촉 기준은 이렇다. 수평판의 각 점에서 수직판까지 가장 가까운 거리를 구하고,
그 거리가 5mm 미만이면 용접선으로 본다. 반대 방향도 같이 한다.
이 방식은 두께와 무관하게 실제로 두 판이 맞닿는 표면을 잡는다.

밴드 반경을 3, 4, 5, 6 mm 로 바꿔가며 비교한 결과 5mm 가 가장 좋았다.
6mm 로 넓히면 용접부가 아닌 판 표면까지 라벨에 들어와 정밀도가 떨어진다.

## 3. 학습

### 배경 자르기가 가장 중요하다

이 작업에서 성능을 가장 크게 올린 것은 모델이나 손실 함수가 아니라 배경 처리다.

받은 점군에는 시편뿐 아니라 촬영 당시 사무실 배경이 통째로 들어 있다.
PTv3 는 좌표를 정규화한 뒤 `grid_size` 로 복셀을 나눈다.
배경까지 포함해 정규화하면 시편이 전체 범위에서 차지하는 비율이 작아지고,
그 결과 복셀 하나가 실좌표로 약 14mm 가 된다.
12mm 판의 접촉 영역은 복셀 하나보다 작아서 통째로 뭉개진다.

시편 경계 상자에서 80mm 여유만 남기고 배경을 자르면 이 문제가 사라진다.

| 조건 | 해양대 용접선 IoU | D04 | D08 | D12 |
| --- | --- | --- | --- | --- |
| 배경 전체 | 37.64 % | 56.8 % | 15.1 % | 0.2 % |
| 배경 크롭 | 72.89 % | 91.9 % | 66.6 % | 42.1 % |
| 배경 크롭 + 두께 균형 | 75.25 % | 92.2 % | 69.7 % | 47.6 % |

D12 가 0.2 % 에서 42.1 % 로 올라간 것이 배경 크롭 하나의 효과다.

### 합동 학습

해양대 데이터만 46건으로 미세조정하면 시드에 따라 결과가 크게 흔들렸다.
NIA 학습 데이터 1,068건을 같이 넣어 학습하면 안정되고 성능도 올라간다.

데이터를 나누는 기준은 시편 회전각이다. 같은 시편을 여러 각도로 찍은 것이라
무작위로 나누면 같은 시편이 학습과 시험에 동시에 들어가 성능이 부풀려진다.

| 구분 | 회전각 | 조건 수 |
| --- | --- | --- |
| 학습 | A000, A010, A030, A050, A130, A140, A160, A170 | 46건 |
| 검증 | A020 | 6건 |
| 시험 | A040, A150 | 12건 |

여기에 두께 균형을 준다. D04 는 1배, D08 은 2배, D12 는 3배로 반복한다.
두꺼운 판일수록 용접선 라벨 점이 적어서 그냥 두면 학습에 거의 반영되지 않기 때문이다.
그 결과 학습 표본이 91건이 되고, 이것을 다시 11배로 반복해 1,001건으로 맞춘 뒤
NIA 1,068건과 합쳐 돌린다.

11배로 맞추는 이유는 두 데이터의 분량을 비슷하게 만들기 위해서다.
한쪽이 20배 많으면 적은 쪽이 학습에 거의 반영되지 않는다.

```bash
bash gpu_run.sh joint_seed.py --seed 42
bash gpu_run.sh joint_seed.py --seed 1
bash gpu_run.sh joint_seed.py --seed 2
```

시드 하나에 약 95분 걸린다. 세 개면 5시간이다.

| 설정 | 값 |
| --- | --- |
| 시작 가중치 | `ptv3_3cls_norgb_8192_lovasz.pt` (NIA 학습 완료본) |
| 입력 점 수 | 8,192 |
| 배치 | 4 |
| grid_size | 0.01 |
| 배경 여유 | 80 mm |
| 에폭 | 60 |
| 손실 | Lovász-softmax + CrossEntropy |

저장되는 가중치는 `/out/kmou_cb_합동_시드{시드}.pt` 다.
시드 42 로 돌린 것은 이름이 `kmou_cb_합동NIA_해양대.pt` 다.

## 4. 추론과 경로 생성

```bash
bash gpu_run.sh make_path_csv.py --weight kmou_cb_합동NIA_해양대.pt --npts 8192 --grid 0.01 --margin 80 --rdp 0.5
```

인자는 학습 때와 같은 값을 써야 한다. 특히 `--npts` 와 `--grid` 가 다르면
복셀 크기가 달라져 결과가 바뀐다.

### 점군에서 선을 뽑는 방법

모델은 점마다 용접선인지 아닌지를 판정할 뿐, 선을 그려주지는 않는다.
용접선으로 분류된 점 무리에서 하나의 곡선을 뽑는 절차는 다음과 같다.

1. 용접선 점들의 주성분을 구해 길이 방향 축을 정한다.
2. 길이 방향으로 5mm 씩 구간을 나눈다.
3. 구간마다 그 안의 점들에 대해 가중 중앙값을 구한다. 가중치는 모델이 낸 확률이다.
   평균이 아니라 중앙값을 쓰는 이유는 잘못 분류된 점 몇 개에 끌려가지 않기 위해서다.
4. 점이 3개 미만인 구간은 버린다.
5. 구간 대표점들을 이동평균 5구간으로 다듬는다.
6. 600점으로 다시 뿌려 매끄러운 곡선으로 만든다.
7. Douglas-Peucker 로 허용오차 0.5mm 안에서 웨이포인트를 줄인다.

5번의 다듬기는 처음에 효과가 없다고 판단했다가 뒤집은 항목이다.
정답 라벨까지의 거리로 재면 나아지지 않는데, 이유는 라벨 자체가 흔들리기 때문이다.
같은 시편을 다른 각도로 찍은 것끼리 비교하는 방법과
판 밑면 평면의 교선에 얼마나 맞는지로 재는 방법을 따로 만들어 확인했더니
두 방법 모두에서 다듬기가 나은 것으로 나왔다.
특히 밑면 교선 기준으로는 40개 조건 전부에서 좋아졌고,
다듬은 경로가 정답 라벨에서 뽑은 경로보다도 밑면 교선에 더 가까웠다.

## 6. 알아둘 점

### 실행마다 결과가 조금씩 다르다

PTv3 추론에 GPU 비결정 연산이 있어서 같은 입력을 같은 가중치로 돌려도
결과가 완전히 같지 않다. 66조건을 세 번 돌려 비교한 실측 폭은 다음과 같다.

| 두께 | 조건별 폭 |
| --- | --- |
| 4 mm | 1.2 %p 이내 |
| 8 mm | 1.3 %p 이내 |
| 12 mm | 최대 6.8 %p |

12mm 이 큰 이유는 라벨 점이 조건당 138점뿐이라 점 몇 개가 뒤집히면
비율이 크게 움직이기 때문이다. 모델이 불안정한 것이 아니라 분모가 작은 것이다.

전체 중앙값으로 보면 3회 실행이 78.52 / 79.08 / 79.74 % 였다.
표에 적은 수치는 한 번의 실행 결과이므로, 다시 돌리면 이 폭 안에서 달라진다.
학습 시드 3개의 평균과 표준편차는 이와 별개로 학습 자체의 재현성을 재는 값이다.

### 평가 방식은 바꾸지 않는다

비교의 일관성을 위해 다음을 고정했다.

- 시드 42 로 8,192점 무작위 추출
- 조건별 IoU 를 평균하지 않고 전 조건을 합쳐 누적 IoU 를 계산
- 경로 통계는 중앙값을 우선 사용
- 학습 시드 3개의 평균과 표준편차를 함께 보고

조건별 IoU 를 평균하면 점이 적은 조건이 과대 반영된다.
누적 IoU 는 전체 점을 대상으로 하므로 그런 왜곡이 없다.

### 남은 한계

12mm 판이 62.60 ± 1.35 % 로 여전히 가장 낮다.
원인은 모델이 아니라 데이터 쪽에 있다.

12mm 조건의 접촉 5mm 라벨은 조건당 중앙값 138점이다.
전체 점군이 약 20만 점이니 0.07 % 다. 4mm 조건의 1,518점과 비교하면 열 배 이상 적다.
두꺼운 판은 수직판 아래쪽이 수평판에 가려져 표면이 잡히지 않는 데다
비스듬히 촬영하면 가려지는 영역이 더 커진다.

배울 점 자체가 적어서 생기는 한계이므로, 개선하려면
12mm 시편을 더 촬영하거나 가려지지 않는 각도에서 추가 촬영을 해야 한다.
현재 12mm 조건은 22건뿐이다.
